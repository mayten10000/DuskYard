# Dusk Yard

Небольшой средневековый двор 28×28 м в сумерках, low-fantasy. Фокус — читаемый ближний бой, контактные VFX, HDRP lighting, Shader Graph и воспроизводимые измерения. Используются реальные PBR-текстуры, процедурная геометрия и тестовый персонаж-стражник. Авторская высокодетальная модель, Animator, AI и UI не требуются исходным PDF.

## Запуск и показ

**Unity 6000.3.5f1 / HDRP 17.3.0.** Открыть папку проекта и `Assets/DuskYard/Scenes/DuskYard.unity`. Нажать Play, кликнуть в Game. Не запускать пустую Untitled.

Готовый player: `Builds/Windows/DuskYard.exe`; из корня проекта — `Play.cmd`. Автоматический 30-секундный показ — `Showcase-30s.cmd`. В Windows ZIP запускать PLAY.cmd / SHOWCASE.cmd после распаковки всего архива. Начальная позиция героя подходит для атаки по мишени. Первый запуск может прогревать шейдеры до начала показа.

| Управление | Действие |
|---|---|
| WASD | Движение |
| Мышь | Обзор |
| ЛКМ / Space | Удар / продолжение комбо |
| Esc / ПКМ | Освободить / захватить курсор |
| F1 | Baseline / Gameplay |
| F2 | Stress / Gameplay |
| F3 | Экспорт ручного замера |
| F4 | Тёплый / холодный пресет VFX |

Ручной сценарий **30 с**: 0–5 — осмотреть двор; 5–15 — три удара; 15–20 — F4 и повтор; 20–25 — отойти и ударить вне дистанции, вернуться; 25–30 — F2, затем выключить и дождаться восстановления. Подробности в **SHOWCASE.md**. Автоматический показ управляет персонажем сам; для ручной проверки использовать обычный запуск.

Комбо: диагональный рубящий → обратный восходящий → сверху вниз. Один удар длится 0.76 с: замах до 0.18, активная фаза 0.18–0.44, завершение/возврат до 0.76. Нажатие после 0.27 с буферизуется; раннее нажатие не пропускает замах. Окно продолжения — 1.05 с после завершения, затем последовательность сбрасывается.

Основная папка — `Assets/DuskYard`. Нумерованные корни сцены: окружение, герой, мишень, камера, свет, контактные VFX, combat/benchmark. Слои: Default — окружение, Target=8, Player=9.

Контакт проверяется capsule вдоль клинка и swept tip, активный интервал делится на шаги до 0.006 с. Выбирается ближайший collider Target, точка уточняется лучом; нормаль задаёт направление частиц. Один контакт на атаку. Точка не задаётся заранее независимо от оружия. След перенесён с начала меча к острию. Вспышка локальная и короткая; вторичные искры затухают. Мишень отклоняется по направлению удара и возвращается строго в исходную позу.

Shader Graph выполняет **два из трёх** требуемых признаков: управляемая HDR-эмиссия и world-space модуляция. Dissolve и triplanar не нужны дополнительно. Свойства Blackboard: **Emission Tint (HDR)** (`_BaseColor`) и **Base Map** (`_BaseMap`); цвет/прозрачность частицы влияют на затухание. Пять VFX-материалов валидируются как Transparent / ZWrite=0 / queue 3000. Это исправляет старый opaque state, создававший видимые квадратные границы. Два основных пресета воспроизводятся F4 и на снимках Gameplay/ColdPreset.

## Свет, материалы и атмосфера

Сумеречное фотографическое HDRI небо; Mixed key 160 lux, baked Sky fill 90 lux и вклад двух жаровен, realtime hero fill 160 lux / тёплый rim 90 candela, короткая контактная вспышка. Цвета ключевого света смягчены, чтобы ткань и кольчуга не терялись в чёрном. Global Volume: фиксированная экспозиция 5, ACES, ColorAdjustments, Bloom 0.02. Декоративного постэффектного стека нет.

Progressive CPU / Shadowmask, lightmap resolution 6 texels/m, atlas 1024, direct 16 / indirect 64 / environment 32 / bounce 2. Итоговый bake: **3 lightmap**, **75 legacy Light Probes**, локальная baked HDRP Reflection Probe. После изменения геометрии свет и отражение запечены заново. Проверки: `Documentation/Verification/bake.txt` и `references.txt`.

Камень, дуб и брусчатка используют albedo/normal/ARM из Poly Haven. HDRP mask собран как R=metallic, G=AO, B=1, A=1−roughness. Масштаб UV камня привязан к мировым метрам. У влажных участков выше smoothness; девять неровных пятен заменили одинаковую сетку луж. Добавлены coping/мерлоны стен, складчатые знамёна, арочный верх ворот, чаши и опоры жаровен с небольшим пламенем. Пламя ограничено max 24 частицами на систему; контактная система отдельно.

Машина: **Intel i7-12650H**, **RTX 4060 Laptop, 7956 МБ**, **RAM 16150 МБ**, Windows 11 build 26300. Нагрузка прочих приложений не изолировалась; результаты относятся к этому запуску на данной машине.

Автопрогон: `DuskYard.exe -benchmark -output <полный путь к новой папке>`. Окно должно быть видимым. Прогрев 12/6/6 с, измерения Baseline/Gameplay по 30 с, Stress 120 с. ## Память и границы вывода

Отдельный запуск: `DuskYard.exe -memory-audit -output <папка>`. После 15 с прогрева и 2 с покоя выполняются GC/inventory и before snapshot; затем 180 с атак,2 с покоя, GC/inventory и after snapshot. Паузы снимков и аллокации инвентаризации не входят в отдельный FPS benchmark. Снимки: native objects + managed heap + native allocations. Анализ выполнен штатным reader Unity через `Editor/DuskYardMemoryAnalysis.cs`, без стороннего runtime-плагина.

Факты аудита: **180.006 с, 235/235 попаданий, 2 успешных snapshot, 0 errors**. Нативных объектов **3865→3865**, загруженных GameObject **346→346**, GPU memory **590786149→590786149 байт**. Эти числа включают inactive/engine objects; активные GameObject в FPS-замере считаются другим API и могут отличаться.

Сравнение snapshot: object memory +3680 байт (ParticleSystem+3840, TrailRenderer−160), без изменения числа объектов каждого типа. Общая native allocation memory +1356046 байт: основная дельта **1310720 байт / 5 allocation** относится к `UnsafeUtility / Malloc(Temp) Pool`; `System / ExecutableAndDlls` +41486, `Objects` +3680, `Malloc(Persistent)` +160 байт. Это фактическая классификация дельты, а не утверждение, что каждый байт доказанно освобождён. Runtime/инвентаризация/снимки имеют собственные расходы. Отдельно сохранены временной ряд памяти, сырые snapshots и сравнение.

В течение проверенного интервала накопления игровых объектов и бесконечного роста частиц не обнаружено; сборки Gen0 в FPS-режимах указаны в таблице. При завершении Development player присутствует `MemoryLeaks`-диагностика Unity около 0.6 МБ с разными engine labels. Она не скрыта и не выдана за установленную утечку игрового объекта; формального доказательства отсутствия любых утечек движка/драйвера нет. Снимки и классификация позволяют проверить ограниченный по длительности тест самостоятельно.

## Оптимизации и ограничения

- В боевом цикле нет Instantiate/Destroy: один контактный ParticleSystem max 256, один свет, общие материалы; 18 частиц обычно, 96 в Stress.
- NonAlloc physics, фиксированные буферы кадров/проб/измерений; нет IMGUI в Update/OnGUI и создания материалов каждый кадр.
- Static batching, запечённый вклад, baked reflection; прозрачные эффекты малы и ограничены по lifetime/числу.
- Stress проверяет повторное использование одного эффекта/мишени, не массовое сражение. Пять ящиков и модульная сцена; персонаж и позы упрощены, без Animator/root motion и сложной IK ног. Камера имеет простую коллизию.
- Визуальный реализм и отсутствие шума проверены по кадрам и показу; это художественная оценка, а не числовой сертификат фотореализма.
- Сборка: 0 errors / 1 warning об отсутствии Unity Cloud access token для загрузки native symbols. Локальная сборка и запуск успешны, Cloud symbols не загружались. Legacy Path Tracing managed reference удалена; свежий preflight проверяет также inactive renderers и managed types.

## Сборка и воспроизведение источников

В готовом проекте повторная генерация не нужна. Финальное меню — **Dusk Yard → Build verified delivery**, метод `DuskYardDelivery.Build`: настраивает/проверяет прозрачность VFX и вызывает preflight/build. `DuskYardFinalize.Validate` проверяет компоненты, материалы, шейдеры, Volume, bake, probes, managed refs и прозрачность.

Генераторы YardBuilder/Finalize/ArtPass/Showcase/VisualPolish оставлены как инструменты разработки. Их повторный запуск может восстанавливать предыдущие этапы геометрии/материалов; не использовать их вместо открытия готовой сцены. Для анализа raw snapshots распаковать Verification ZIP в Deliverables и вызвать `DuskYardMemoryAnalysis.Run`.

Git исключает Library/Temp/Logs/UserSettings/Builds и локальную историю. Source ZIP — текущее состояние; **DuskYard.bundle** содержит репозиторий с историей (`git clone DuskYard.bundle DuskYard`). `LightingData.asset` помечен binary, его байты и состав ZIP проверяются перед передачей; контрольные суммы — Deliverables/SHA256.txt.

## Комплект и соответствие

**SUBMISSION.md** описывает файлы для передачи и содержит заготовку сопроводительного сообщения. **Documentation/REQUIREMENTS.md** — 70 атомарных условий исходного PDF с реализацией и доказательствами; исходник/извлечённый текст/SHA256 приложены. **TIMELOG.md** честно отделяет измеренные интервалы тестов от отсутствующего исторического учёта по блокам. Он не восстановлен задним числом.

По предыдущему решению пользователя комплект пока локальный. Для внешней сдачи потребуется загрузить проект/репозиторий и отдельный Windows build на выбранный диск и дать реальные ссылки. Локальные пути не выдаются за облачные. Полное безусловное соответствие не заявляется в части неизвестного исторического времени и ещё не созданной внешней ссылки.
